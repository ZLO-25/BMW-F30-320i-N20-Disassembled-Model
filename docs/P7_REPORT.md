## 1. 效能：為什麼手機會卡，我怎麼修

### 先講觀念：draw call

GPU 畫畫面時，每一塊獨立的 3D 物件（mesh）都要 CPU 下一次命令，叫 **draw call**。
手機 CPU 弱，一個畫面下幾百次就開始掉幀。

我們的零件是程式拼出來的：一個缸頭由幾十塊小方塊、小圓柱拼成，每塊都是一個 mesh。

```
改之前（一個零件）                     改之後（同一個零件）
┌ 缸頭                                ┌ 缸頭
├ 鋁塊 ①  ─ draw call                 ├ 鋁（①②③ 合成一塊）─ draw call
├ 鋁塊 ②  ─ draw call     合併同材質   ├ 鋼（④⑤ 合成一塊） ─ draw call
├ 鋁塊 ③  ─ draw call   ───────────►  └ 'spin'（動畫要轉，保留）
├ 鋼件 ④  ─ draw call
├ 鋼件 ⑤  ─ draw call
└ 'spin'（動畫要轉它）
```

重點規則：**有名字的子物件不合併**（動畫靠名字找到它，例如壓板的每一根彈簧指）。
每個零件仍然有自己的材質，所以點選高亮、透視、隱藏都照舊。

### 量到的數字（同一個畫面，雲端軟體繪圖量測）

| 畫質 | 改之前 draw call | 改之後 | 減少 |
|---|---|---|---|
| 手機（low） | 1,074 | 349 | −68% |
| 中階電腦（mid） | 1,165 | 351 | −70% |
| 高畫質（high，含陰影） | 2,616 | 735 | −72% |

三角形數量不變，看起來一模一樣，只是 GPU 少做很多次切換。

### 另外三件事

| 做了什麼 | 白話說明 |
|---|---|
| 自動降解析度 | 連續掉到 30 fps 以下，就把畫面像素比從 1.5 降到 1，順了再升回去 |
| 程式分包 | three.js（很少改）和我們的程式（常改）分開打包，改版後瀏覽器只要重新下載小的那包 |
| `?stats=1` 效能面板 | 網址後面加 `?stats=1`，左下角會顯示 FPS、draw calls、三角形數 |

### 誠實說明：30 fps 要在真手機上量

雲端環境沒有顯示卡，是用 CPU 模擬繪圖（每秒只有 1–5 幀，不代表真實速度）。
所以「中階手機 30 fps」這一項**我沒辦法替你量**。請你用手機開：

```
https://zlo-25.github.io/BMW-F30-320i-N20-Disassembled-Model/?stats=1
```

看左下角的數字。如果低於 30，再加 `&quality=low` 比較看看，把結果告訴我。

### 沒做的（以及原因）

| PLAN 原本寫的 | 結果 | 原因 |
|---|---|---|
| instancing | 沒做 | 合併後已經不是瓶頸；instancing 會讓「單獨高亮一顆零件」變複雜 |
| 距離 LOD | 改成依裝置選面數 | 距離 LOD 要同時產生三份模型，載入時間和記憶體都變三倍 |
| 各系統分包延遲載入 | 沒做 | 全部資料只有約 400 KB，3D 一開始就要用，延遲載入省不到時間 |

## 2. 資料查證回顧

規則不變：**找得到可信來源才填，找不到就留空白（待查證）**。

| 項目 | 結果 | 來源 |
|---|---|---|
| 機油濾芯蓋扭力 | 25 Nm（社群） | FCP Euro N20 換機油教學 |
| 前碟盤直徑（左右） | 300 mm（標準煞車） | Brembo 零件目錄 F30 320i |
| 後碟盤直徑（左右） | 300 mm（標準煞車） | Brembo 零件目錄 F30 320i |
| 換機油導覽：機油量 | 約 4.5 L（社群） | FCP Euro |
| 放油螺絲扭力 | **維持待查證** | FCP Euro 寫「最大 8 Nm」，其他網站寫 25 Nm，兩邊矛盾 |
| 輪圈螺絲、火星塞扭力與間隙、卡鉗螺絲 | 維持待查證 | 這輪只找到沒附來源的網站，不採用 |

```
待查證比例： 84.1%  ──►  82.4%
             (243/289)     (238/289)
```

M Sport 煞車的碟盤比較大（前 340 mm、後 345 mm），寫在零件說明裡。

**為什麼還有八成待查證？** 扭力、料號這類數字真正可靠的來源是 BMW 原廠維修資料（ISTA / TIS）和原廠零件目錄（ETK）。這些需要帳號或付費，我拿不到。
如果你有管道（例如認識的技師可以查 ISTA），把數字和截圖給我，我就能一次把一大批改成「verified」。

## 4. 怎麼測

| 測什麼 | 怎麼做 | 預期 |
|---|---|---|
| 線上版 | 手機和電腦都打開上面的網址 | 跟本機一樣，可以拆、可以看動畫 |
| 手機效能 | 網址加 `?stats=1` | 左下角顯示 fps，目標 ≥ 30 |
| 合併網格沒弄壞動畫 | 運轉動畫 → 踩離合器，拉滑桿到底 | 彈簧指一根根翹起來，壓環退開 |
| 比較合併前後 | 網址加 `?stats=1&merge=0` | draw calls 會變成三倍左右 |
| 資料 | `npm run validate`、`npm test`、`npm run report:verify` | 全部通過，報表 82.4% 待查證 |

我在雲端做過的檢查：
- 64 項單元測試全部通過，其中 2 項是新的。它們檢查每個程式化零件合併後名字不少、外形不變、外殼標記還在。
- 瀏覽器實測離合器動畫，合併和不合併的結果一模一樣：彈簧指從 0.25 轉到 −0.25，壓環從 0.006 移到 −0.002。過程中沒有任何錯誤。
- 保養分頁和故障情境的完整流程又跑了一次。
