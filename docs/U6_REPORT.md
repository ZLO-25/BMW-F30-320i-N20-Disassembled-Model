# U6 報告：材質與光影升級（不換模型）

日期：2026-11-02　狀態：**完成，未提交、未推送，等 ZL 確認**

## 0. 我理解的目標與問題

**目標**：不換掉現有的程式化模型（ZL 覺得它比 text-to-cad 版好看），只靠「表面質感」和「光影」讓整台車看起來更像真的金屬與塑膠，拿去教學時更有說服力。

**要解決的問題**：

```
  U6 之前的零件表面                          問題
  ┌──────────────┐
  │              │   1. 太乾淨：鑄鋁、鑄鐵、塑膠只差在顏色與亮度，像打光的玩具
  │   一片均勻    │   2. 沒有接觸陰影：零件疊在一起時縫隙不會變暗，看起來「飄」在空中
  │              │   3. 舊的雜訊貼圖靠 UV，大零件顆粒巨大、小零件看不到（尺寸亂跑）
  └──────────────┘   4. 以後若再載入 GLB，它的材質和程式化零件不一致
```

## 1. 做了什麼

### 1-1 四種程式產生的表面紋理（`src/scene/procedural/grain.ts`）

不連網、不用圖片檔，App 開啟時用程式算出 4 張 128×128 的小貼圖：

| 表面 | 用在哪些 `M.*` | 長相 |
|---|---|---|
| 鑄鋁砂面 `castAl` | `castAl`、`forged` | 細砂顆粒 + 大片深淺斑駁 |
| 鑄鐵 `castIron` | `castIron`、`hotIron` | 較粗顆粒 + 小砂孔 |
| 紋理塑膠（咬花）`plastic` | `blackPlastic`、`greyPlastic` | 一顆顆細小凸點 |
| 加工面 `machined` | `steel`、`darkSteel`、`machinedAl` | 沿 X 方向的車削 / 拉絲細紋 |

一張貼圖的三個顏色通道各放一種資料（只取樣一次就拿到三種）：

```
  R 通道 ──► 凹凸高度（讓光線在表面產生細小明暗）
  G 通道 ──► 粗糙度細變化（有的地方亮一點、有的霧一點）
  B 通道 ──► 大範圍斑駁（放大很多倍貼，遠看也看得到鑄件的深淺不一）
```

**關鍵技巧：三面投影（triplanar），不靠 UV。**

```
   舊方法（UV）                               新方法（三面投影）
   每個零件的 UV 都是 0..1                     用零件自己的座標（公尺）來貼

   大缸體 ┌────────────┐  小螺栓 ┌─┐           每公尺固定 N 格紋理：
          │ 3×3 格紋理  │        │3×3│          大零件 = 很多格、小零件 = 少少幾格
          └────────────┘        └─┘           → 顆粒大小一致，和真實世界一樣
   → 大零件顆粒巨大、小零件糊成一片
```

依表面朝向混合三個方向的投影（朝上的面用 X-Z 平面、朝側面的用 Z-Y 平面…），所以沒有接縫。
拆下 / 動畫移動零件時，紋理跟著零件走（用的是零件本身座標，不是世界座標）。

**亮度不變**：粗糙度貼圖是「乘上去」的，會讓平均變亮一點，所以 `registry.ts` 的 `grained()` 先把底值除回去，整體亮度和 U6 之前差不多，只是多了細節。

### 1-2 環境遮蔽 AO（`src/scene/Scene.tsx` 的 `PostFX`）

AO 就是「角落、縫隙、零件靠很近的地方，環境光照不進去，所以比較暗」。

```
  一般繪製 ──► 深度圖 ──► N8AO：算每一點周圍被擋住多少 ──► 縫隙變暗 ──► ACES 色調 ──► 畫面
                                (半徑 0.15 m ≈ 零件縫隙尺度)
```

| 畫質 | AO | 設定 |
|---|---|---|
| high（桌機） | 開 | 全解析度、quality medium、強度 3、4× 多重取樣抗鋸齒 |
| mid（較強手機 / `?quality=mid`） | 開 | 半解析度、quality low、強度 2.5 |
| low（一般手機） | **關**（整段不掛，和 U6 前一模一樣） | — |

- 環境光**維持** `RoomEnvironment`，沒有改回 drei `<Environment preset>`。
- 新增 `?ao=0` 可以強制關 AO（比較前後、或電腦太慢時用）。
- 套件：`@react-three/postprocessing`（MIT）、`postprocessing`（Zlib）、內含 `n8ao`（CC0）。都會打包進 App，離線可用。

### 1-3 GLB 材質自動對應 M.*（`src/scene/procedural/materialMatch.ts`）

```
  GLB 材質名稱含 alu / iron / plastic / steel / rubber …  ──► 對應的 M.*
  名稱看不出來 → 看顏色 + 金屬度（灰階才換）               ──► M.castAl / steel / castIron / 塑膠
  有顏色的（車漆、橘色標籤）或透明的（玻璃、燈殼）         ──► 保留模型原本的材質
```

目前 App 沒有用到 GLB（U0 已還原），這是為以後載入外部模型準備的；有 Vitest 測試。
順便把 ZL 電腦上那個「GLB 節點名稱有 `.` 找不到」的修正也放進來了（用 three 的 `sanitizeNodeName` 兩種名字都找），
所以雲端版和 ZL 本機版的 `ModelResolver.tsx` 不會再不一樣（ZL 本機那份可以直接被這份取代）。

### 1-4 配合 AO 的兩個修正

開 AO 後畫面是在「線性色彩」裡合成，最後才套 ACES，會造成兩個副作用，已補償：

| 副作用 | 原因 | 修正 |
|---|---|---|
| 背景、格線變得幾乎全黑（21 → 6） | ACES 也套到背景上 | AO 開啟時背景給較亮的顏色，算完 ACES 剛好回到原本的 `#15171b`（實測 21,23,27 → 22,24,28） |
| 透視模式的車殼變成一層濃濃的藍霧 | 半透明在線性空間疊加，看起來濃很多 | `PartNode.ghostTuning.scale`：AO 開啟時透明度 × 0.3 |

另外：`?stats=1` 的 draw calls / 三角形數改成「整個畫面的總和」。原本 three 每次 render 都歸零，掛了後處理後只會看到最後一步（1 個 draw call）。

## 2. 數字（`?stats=1`，1000×640 視窗，預設視角）

> ⚠️ 雲端沒有顯示卡，是**軟體繪圖（SwiftShader）**，fps 只有 0–3，不能代表真實裝置。draw calls 和三角形數是準的。

| 畫質 | | draw calls | 三角形 | fps（軟體繪圖） |
|---|---|---|---|---|
| high | U6 前 | 741 | 872,640 | 1 |
| high | U6 後 | 768（+27） | 897,314（+2.8%） | 0 |
| mid | U6 前 | 357 | 202,942 | 2 |
| mid | U6 後 | 384（+27） | 214,479（+5.7%） | 1 |
| low | U6 前 | 355 | 73,458 | 3 |
| low | U6 後 | 355（不變） | 73,458（不變） | 3 |

- 多出來的 draw calls 是後處理的幾個步驟（AO 計算、去雜訊、合成、色調），和零件數量無關。
- 模型本身完全沒變（`geometries` 只多 2 個 = 後處理用的全螢幕三角形）。
- 紋理不會增加 draw call：同一種表面的零件共用一張貼圖、一個 shader 程式，合併網格照舊。
- 打包大小：`vendor` 582 KB → 808 KB（gzip 179 → 280 KB），多的是後處理套件。

## 5. 已知問題

1. **透視模式的引擎蓋上有一塊亮白反光**（high / mid）。原因同 1-4：車漆的高光在線性空間是很亮的數值，即使透明度很低還是會透出來。要壓掉可以在透視時降低車殼的環境反射，但會讓車殼更不明顯，想先問你要不要。
2. 紋理在預設視角（離引擎 2 公尺以上）很淡，拉近才明顯 — 這是刻意的：真實鑄件的砂面顆粒只有 1 mm 左右，遠看本來就看不到；遠看靠 B 通道的大片斑駁和 AO 撐質感。如果想要更誇張一點，改 `grain.ts` 的 `GRAIN_SETTINGS`（一處改、全部生效）。
3. **手機 30 fps 還沒驗證**。low 畫質沒開 AO，只多了每個像素幾次貼圖取樣，預期影響很小；mid 畫質（較強的手機）有開半解析度 AO，需要實機確認。
4. 紋理是示意的「表面質感」，不是任何零件的實際規格，不影響 `data/` 的數值，也不需要登記來源。
