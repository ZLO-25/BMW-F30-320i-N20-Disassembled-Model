# E0–E6 報告：執行效能與 UIUX 優化（2026-11-12）

規劃文件：Claude Doc「N20 模擬器：效能與 UIUX 優化規劃（E0–E6）」。量測腳本與數字見 `docs/PERF_BASELINE.md`、`docs/perf/latest.json`、`docs/e5/metrics.json`。
**這份報告的數字都是雲端 headless（沒有顯示卡、軟體繪圖）量的。真實 FPS 還沒有，請照最下面「請 ZL 做的事」在電腦與手機各跑一次 `?bench=1`。**

## 一句話

以前是「每秒 60 次把整條管線全開地重畫，連沒人在看也畫」；現在是「靜止不畫、轉動時只畫該畫的、畫質依裝置與實際 FPS 自動調、打開有載入畫面」。

```
              以前                                    現在
  ┌─────────────────────────┐            ┌──────────────────────────────────┐
  │ 每格：陰影圖 + 主畫面 +  │            │ 靜止：0 格                        │
  │       AO + Bloom + 4xMSAA│            │ 轉鏡頭：主畫面 (+AO)，陰影圖不重畫│
  │ 靜止也一直畫             │            │ 有東西動：陰影圖才更新            │
  │ 桌機一律最高畫質         │            │ 畫質 L0–L5，自動降級、可手動選    │
  └─────────────────────────┘            └──────────────────────────────────┘
```

## E0 量測工具
- `?bench=1`：一鍵跑分（鏡頭繞一圈 6 秒），中央顯示可複製的結果（平均 FPS、每格 p50/p95、畫質、像素比、顯示卡、載入到第一格）。
- `npm run perf`：headless 量 high/mid/low 全部數字 → `docs/perf/latest.json`；`npm run ui`：介面版面與按鈕大小 → `docs/e5/`；`npm run shots:quality`：L0–L5 截圖 → `docs/e2/`。
- `PerfStats` 多了每格 p50/p95、程式數、貼圖數、累計畫格數、`__n20gl`、`__n20pick`（射線計時）。
- **驗證了兩個推論**：F11（拉近鏡頭多編譯 17 支著色器）與 F12（貼圖漏失，來源是接觸陰影）都是真的。

## E1 靜止不畫
- Canvas `frameloop="demand"`；`InvalidateOnStore`（store 任何改變就重畫）+ `redraw()` 小工具（`src/scene/redraw.ts`）。
- 陰影圖凍結：只在有東西移動／顯示／隱藏時更新（high 轉動時每格少畫一整台車）。
- 工作燈改成一直在場景裡、遠處強度 0（不再切 visible → 不再重編著色器）。
- 接觸陰影改寫成自己管理的元件（`ContactShadowPlane`），卸載時釋放渲染目標（drei 版不會 → 貼圖漏失）。
- 拿掉 `PerformanceMonitor`（按需渲染下它會把「沒在畫」誤判成低 FPS），由 E2 的 `QualityGovernor` 取代。
- **怎麼驗**：`npm run e2e` 新增 12 項「操作後畫面真的變、然後停」檢查（拖曳含慣性、爆炸圖、剖面、背景、車殼三模式、拆下、動畫）+ 閒置 3 秒 0 格。全過。

## E2 畫質
- `src/core/quality.ts`（純邏輯 + 15 個測試）：六級 L0–L5；起點 = 網址 > 儲存值 > 猜（手機 L1／4 核以下 L0；桌機看顯示卡名稱，內顯或讀不到 → L3，其他 → L4）。
- `QualityGovernor`：連續在畫時，兩個 1 秒窗口中位數 > 28 ms 就降一級（只降不升，載入後 2 秒不量，靜止空檔不算），並跳提示、存起來。
- 檢視工具新增「畫質：自動／流暢／均衡／精緻」，會記住；手動選的不會被自動降。網址 `?quality=low|mid|high` 照舊（對應 L0/L1/L5），新增 `?level=0..5`。
- AO 可以執行中關閉：透視透明度補償跟著切（L2 與 L3 同視角截圖濃淡接近）。
- 截圖：`docs/e2/level_0.jpg … level_5.jpg`（同一視角）。

## E3 載入
- `index.html` 純 HTML 載入畫面（中英、進度條 10 → 33 → 66 → 100%），第一格畫出來才淡出。
- 第一格前先 `compileAsync` 編譯著色器（Canvas 在這之前 `frameloop="never"`）。**效果要看實機**：支援平行編譯的瀏覽器上才不卡；不支援就退回和以前一樣。
- 後處理（N8AO、postprocessing）改延遲載入（`postfx` chunk，100 KB gzip），L0/L1 不下載；教學資料（導覽、題庫、保養、情境，39 KB gzip）改成點開學習／保養分頁才載入。
- 首包 622 → 513 KB gzip（目標 500，**差 13 KB**；再縮要動 three / drei 的引入方式，風險高，先不做）。分包循環檢查：vendor 沒有 import postfx，e2e 通過。

## E4 操作反應
- 射線加速：three-mesh-bvh（鎖 0.8.3，和 drei 同一版），建樹排進閒置時間分批做（high 共約 290 ms，不卡載入）；一次射線 3.7 → 0.7 ms（mid）。
- 拖曳超過 4 px 才暫停偵測（單純點一下不受影響）；觸控略過 hover。
- 零件樹節點只訂閱「是不是我」的布林值（滑鼠掃過不再讓全部節點重渲染）；隱藏的分頁不掛載（零件樹保留）；動畫滑桿改用 `subscribe` 直接寫值。
- 說明：規劃估計的「16 ms」是整段 JS（含 React 重渲染）的粗估，射線本身實測只有 3.7 ms，所以這一項的實際收益比預期小，主要收益在 React 重渲染與拖曳時不做偵測。

## E5 介面
- 手機：頂端壓成一排（車名縮短 + 檢視／拆裝 + 復原 + 重做 + ⋯），變速箱／車殼／重置視角／語言／關於收進 ⋯；免責聲明可關（「關於」保留全文）；3D 畫面 328 → 458 px。
- 觸控目標：手機 44 px、桌機 24 px（手機小按鈕 188 → 1，桌機 55 → 0）。
- 側欄分頁：圖示在上、字在下、不折行；`role=tablist`、左右鍵切換；「運轉動畫」→「動畫」。
- 預設視角依畫面長寬比退到看得到整台車；資訊卡新增「🎯 看這個零件」（選取時不自動移鏡頭）。
- 檢視工具的系統清單依大系統分組、可收合（預設只展開引擎），手機面板高度 ≤ 60%。
- 第一次使用三步引導（可略過，存 `n20.onboard.v1`）。
- low 畫質的輪圈、碟盤 8 邊 → 16 邊（輪胎 12 → 20 段），low 三角形增加 < 5%。
- 截圖：`docs/e5/`（桌機 1366×768、手機 390×844）。

## 已知問題與限制
- 雲端沒有顯示卡：每格毫秒與 FPS 只能比大小；`compileAsync` 的效益、自動降級的門檻（28 ms）、各級起點都要等實機數字微調。
- 慣性滑行（拖曳放開後）要畫約 60 格才停，這是 OrbitControls 阻尼的設計，不是漏停。
- 切換畫質到 L2（原生抗鋸齒）會重建畫布，視角會回到預設。
- `?bench=1` 在手機上要用「複製結果」貼回；複製失敗時可手動選取文字。
