# 開發計畫（PLAN）— BMW F30 320i（N20）互動式拆解教學模擬器

> 狀態：P0 第二版（Fable 複審後修正），等你確認後才開始 P1
> 最後更新：2026-10-25
> 複審改了什麼：見文末「P0 複審紀錄」

---

## 1. 我理解的目標

做一個「瀏覽器裡的虛擬修車廠」：DIY 車主可以把 F30 320i 從外到內一層層拆開、裝回去。
重點不只是「看 3D」，而是**透過拆裝學會燃油車的通用原理**，再認識 BMW 自己的做法。

要解決的問題：
1. 市面上沒有能拆的 N20 免費模型 → 用程式拼出零件。
2. 維修資訊散落、很多數字來源不明 → 每個數字都要附來源，查不到就標「待查證」。
3. 新手不知道從哪學起 → Lv1 到 Lv5 的學習路徑，加上導覽、測驗、故障任務。

## 2. 技術選型與理由

| 項目 | 選擇 | 理由 |
|---|---|---|
| 建置 | **Vite + TypeScript** | 照需求；建置快，輸出純靜態檔，可放 GitHub Pages |
| 3D | **Three.js + react-three-fiber（R3F）+ drei** | 見下方說明 |
| UI | **React 18** | 零件樹、資訊卡、測驗、保養分頁都是大量 UI，用 React 寫比手刻 DOM 好維護 |
| 狀態 | **Zustand** | 輕量，R3F 官方同一團隊（pmndrs）出品，3D 與 UI 共用同一個 store |
| 資料驗證 | **Zod** | 啟動時與建置時檢查 JSON，格式錯就報錯，避免壞資料默默上線 |
| 測試 | **Vitest** | 測拆裝相依邏輯（`requires` 圖、循環偵測、復原/重做） |
| 路由 | **HashRouter** | GitHub Pages 沒有伺服器端路由，用 `#/` 最省事 |
| 雙語 | 自寫輕量 i18n（`{zh, en}` 物件 + `t()`） | 資料本來就是 `{zh,en}`，不需要 i18next 那麼重 |

### 為什麼選 R3F，而不是純 Three.js

```
純 Three.js                              R3F
─────────────────────────────            ─────────────────────────────
場景與 UI 要各自同步狀態                  零件 JSON → React 元件 → 場景，單向資料流
點選、hover 要自己寫 raycast              onClick / onPointerOver 直接寫在物件上
LOD、OrbitControls、剖面要自己接          drei 現成：<Detailed>、<OrbitControls>、
                                          <Bvh>（加速點選）、useGLTF、<Bounds>
效能：最直接                              效能：幾乎一樣；動畫用 useFrame 直接改物件，
                                          不經過 React 重繪
```

結論：這個專案「UI 和資料」佔的比重比「3D 特效」大，R3F 讓資料驅動場景最自然。

## 3. 整體架構

```
┌──────────────────────── data/（JSON，只改這裡就能加零件）─────────────────┐
│ parts/*.json   procedures/*.json   quizzes/*.json   scenarios/*.json      │
│ maintenance/*.json   sources.json（來源清單）                              │
└──────────────┬───────────────────────────────────────────────────────────┘
               │ Zod 驗證
               ▼
┌──────── src/core（純邏輯，沒有 3D、沒有 React，可單元測試）──────────────┐
│ partGraph：父子樹 + requires 相依圖 + 循環偵測                             │
│ disassembly：canRemove / remove / install / undo / redo                  │
│ variant：手排/自排過濾   progress：localStorage（try/catch）              │
└──────────────┬───────────────────────────────────────────────────────────┘
               │ Zustand store
       ┌───────┴────────┐
       ▼                ▼
┌─ src/scene ─────┐  ┌─ src/ui ────────────────────────────┐
│ ModelResolver   │  │ 零件樹、資訊卡、托盤、工具列         │
│  procedural:xx  │  │ 導覽、測驗、故障任務、保養、關於     │
│  glb:/models/xx │  └─────────────────────────────────────┘
│ 爆炸圖、剖面    │
│ 動畫            │
└─────────────────┘
```

### modelRef 互換機制（需求 3-4）

```
"modelRef": "procedural:chain_v1"          → 查 procedural 註冊表，呼叫產生器
"modelRef": "glb:/models/n20.glb#Chain"    → 載入 GLB，取名為 Chain 的節點
```
兩種都輸出同一種東西（一個 Three.js 物件），外面的程式不知道也不在乎它從哪來。
換模型只要改 JSON 的一個字串。

### 拆裝的三條規則（複審新增，這是整個模擬器的核心語意）

```
規則 1：拆一個零件，它底下的子零件一起跟著走（整個次總成一起拿下來）
        例：拆進氣歧管時，裝在上面的節氣門一起下來，不用先拆節氣門

規則 2：requires 是「例外清單」：列出的零件必須先單獨拆掉
        例：正時鏈 requires 氣門室蓋 → 氣門室蓋沒拆就不能動正時鏈

規則 3：裝回去的順序 = 拆下來的反順序（托盤是一個堆疊）
        想裝 A，但 A 擋住的東西還在托盤裡 → 提示先裝那個
```

這三條都在 `src/core/disassembly.ts` 實作，用 Vitest 鎖住行為，之後任何零件資料都要通過這套檢查。

### 已知技術限制（先講清楚，免得之後失望）

| 功能 | 做法 | 限制 |
|---|---|---|
| 剖面切割 | Three.js `clippingPlanes` | 切開的地方是「空心」的，不會畫出實心斷面（封蓋要另外算，P7 若有餘裕再做） |
| 托盤拖回原位 | 先做「點托盤零件 → 自動飛回原位」；拖曳在 P2 後半才加 | 手機上拖曳 3D 物件容易和旋轉相機打架，所以點選是主要操作，拖曳是加分 |
| 外觀車殼 | 簡化幾何（P1） | 看得出是四門轎車的輪廓與 F30 的比例，但不會有真車的曲線；之後可換 GLB |
| 動畫 | 關鍵影格 + `useFrame` | 不做物理模擬，齒輪嚙合是視覺示意 |

### 效能策略（從 P1 就照做，P7 再收尾）

- 螺絲等重複零件用 **InstancedMesh**。
- 程式化零件的產生器都接受 `detail` 參數，產出高/中/低三種面數，交給 `<Detailed>` 做 LOD。
- 各系統（引擎、變速箱、底盤…）的資料與模型**分包延遲載入**，進到該系統才載。
- 點選用 `three-mesh-bvh` 加速。
- 手機自動降低 `devicePixelRatio`（上限 1.5），關閉陰影。

## 5. 資料可信度政策

```
confidence      顏色    意思
─────────────────────────────────────────────
verified        綠      原廠文件或原廠零件目錄
community       黃      可信的維修網站、DIY 教學、論壇共識
unverified      灰      查不到，數值一律是 null，介面顯示「待查證」
```

- 扭力、容量、尺寸、料號：**沒有來源就填 `null`**，不估計、不憑記憶。
- 「關於」與首頁都顯示：「本工具為教學用途，實際維修請以原廠維修手冊為準。」
- 一次性螺絲（TTY bolt）在介面上特別標紅。

## 6. 開工前想請你確認的問題

1. **你的車是哪一年、哪個市場？** 複審時發現我原本說「2015 改款後 320i 都改用 B48」不精確：零件目錄顯示 N20 版 320i 在部分市場（含型號代碼 8A01）生產到 2018 年 10 月。所以年份影響的主要是**外觀（LCI 前後的頭尾燈）**，引擎與變速箱都還是 N20 + 8HP45 / GS6-17BG。我預設「**台灣規格、左駕**」，外觀先做 LCI 前的樣子。如果你的車是 LCI 後的，告訴我一聲，外觀改一下就好。
2. **車殼模型**：要我先用簡化幾何拼車殼（安全、無授權風險），還是你願意手動下載 MODEL_SOURCES.md 的 #1 候選？我建議先用簡化幾何，之後再換。
3. **R3F + React** 這個選擇可以嗎？
4. **部署**：要放在哪個 GitHub repo？（P7 才需要，現在先不急。）

你在 2026-10-25 回了「繼續」，我解讀為同意預設答案（台灣左駕、簡化車殼、R3F）。

## P3 實作備註（2026-10-26）

| 項目 | 決定 | 原因 |
|---|---|---|
| 變體怎麼切 | 零件資料全部放一起，載入時 `buildGraph(parts, variant)` 過濾；`requiresVariant` 併進 `requires` | 拆裝規則不用知道變體存在，測試只要兩個變體各跑一次 |
| 預設變體 | 自排，開站不跳選擇視窗（使用者 10/26 要求） | 大多數 320i 是自排，先看到主畫面比較直覺 |
| 切換變速箱 | 托盤有東西時先確認，然後全部歸零 | 兩種變速箱是兩個世界，托盤裡的手排零件在自排世界沒有位置 |
| 離合器三件、驅動盤 | 掛在引擎總成下（曲軸端），不在變速箱總成下 | 現實上拆變速箱後它們留在引擎上；資料上也讓「壓板要先拆變速箱」成立 |
| 動畫 | 不做物理，用 `useFrame` 依滑桿或檔位改子物件的位置 / 顏色 | 教學要的是「看得懂」，不是真實轉速 |
| 手排齒比 | 示意值並明確標示 | 沒查到 GS6-17BG 可信齒比，不填真實感的假數字 |
| 對照模式 | 獨立覆蓋畫面、獨立 Canvas | 主畫面的托盤 / 剖面 / 爆炸圖狀態不會汙染對照畫面 |

| 導覽怎麼動 3D | `remove` / `install` 步驟按「做這一步」走正常的 tryRemove / tryInstall；用到的工具自動放到手上 | 導覽教的是正確做法，不該在導覽裡跳錯誤示範；而且零件已拆 / 已裝會自動打勾，學員自己先拆了也不會卡住 |
| 錯誤示範何時觸發 | 只在「規則上拆得下來」之後才檢查 mistakes；被 requires 擋住的先顯示「必須先拆」 | 兩種提示疊在一起會搞混；拆不下來談不上做錯 |
| 錯誤的後果怎麼呈現 | 對話框 + 紅色提示列顯示後果文字，記進 localStorage；**不做**爆炸、氣門撞活塞的 3D 動畫 | 文字後果已達教學目的；每種錯誤做動畫成本高，P6 情境任務需要時再做 |
| 手上的工具 | 資訊卡「工具」區變成可勾選；只有 `remove_without_tool` 會看它 | 不想在每次拆零件時都強迫選工具，會變成打卡；只在有危險的零件上才要求 |
| 解鎖 | Lv1 永遠開；LvN 要 Lv(N-1) 最佳成績 ≥ passPct；設定可整個關掉 | PLAN 要求；老師投影示範時要能直接跳 Lv4 |
| 題目 | 每級 4 題示範題（共 20），identify 題在 3D 亮零件 | 讓解鎖真的跑得起來；P6 補到 ≥ 50 題 |
| 進度存哪 | localStorage `n20.progress.v1`，包 try/catch | PLAN 要求；沒有後端 |
| 扭力 | 導覽步驟的扭力全部 null / 待查證，介面寫「請查原廠手冊」 | 沒有可信來源就不填（資料不准瞎編） |

## P7 實作備註（2026-10-26）

| 項目 | 決定 | 原因 |
|---|---|---|
| 合併網格 | 每個零件載入時，把「外觀一樣」的小 mesh 合成一塊；有名字的子物件保留 | draw call 是手機最大瓶頸（1,074 → 349）。保留每個零件自己的材質，高亮、透明化、點選都不受影響 |
| instancing | 沒有另外做 | 合併後重複的小零件（螺絲、彈簧指）已經不是瓶頸；instancing 會讓「單獨高亮某個零件」變複雜 |
| LOD | 依裝置選高 / 中 / 低三種面數，不做距離切換 | 距離 LOD 要同時產生三份模型，載入時間和記憶體都變三倍；這個場景鏡頭多半很近，效益小 |
| 自動降解析度 | drei `PerformanceMonitor`：低於 30 fps 把像素比降到 1 | 手機最直接有效的一招，不影響模型 |
| 延遲載入 | 只把 three.js 拆成獨立檔案，不做系統分包 | 資料全部只有約 400 KB；3D 是主畫面，一開始就要用，延遲載入省不到時間 |
| 30 fps 驗收 | 雲端沒有真手機（只有軟體繪圖），所以用 `?stats=1` 讓你在自己手機上量 | 不想用模擬器的數字假裝通過 |
| 查證回顧 | 只補找得到可信來源的值；來源互相矛盾就維持待查證並寫明 | 符合「不憑記憶填規格」 |
